# GitHub Copilot Instructions for Playwright TTACart Project

## Test Case Development Guidelines

When helping with test case development, code generation, or modifications to this Playwright project, please follow these mandatory rules:

### Every Time a Test Case is Added or Modified

1. **Always recommend running Type Check:**
   ```bash
   npm run type-check
   ```
   Explain that this ensures all TypeScript types are correct.

2. **Always recommend running Lint Check:**
   ```bash
   npm run lint
   ```
   Explain that this ensures code follows the project's style and quality guidelines.

### Code Generation Best Practices

When generating or suggesting code for this project:

- **Use Page Object Model (POM) pattern** for all UI interactions
- **Create Page Objects in `src/pages/`** for each page/component
- **Place test cases in `src/tests/`**
- **Add test data to `src/testdata/`**
- **Use path aliases** for imports:
  - `@pages/*` for page objects
  - `@api/*` for API utilities
  - `@testdata/*` for test data
  - `@fixtures/*` for fixtures
  - `@config/*` for configuration
  - `@utils/*` for utility functions

### Test Structure

When creating test cases, use this structure:

```typescript
import { test, expect } from '@playwright/test';
import { YourPageObject } from '@pages/YourPageObject';

test.describe('Feature Name', () => {
  let page;
  let pageObject;

  test.beforeEach(async ({ page: testPage }) => {
    page = testPage;
    pageObject = new YourPageObject(page);
    await pageObject.goto();
  });

  test('@p0 should do something', async () => {
    // Arrange
    // Act
    // Assert
  });
});
```

### Important Rules to Enforce

- [ ] All new tests must pass `npm run type-check`
- [ ] All new tests must pass `npm run lint`
- [ ] Use TypeScript strict mode
- [ ] Add appropriate test tags (@p0, @p1)
- [ ] Use descriptive test names
- [ ] Follow the project's folder structure
- [ ] Always use page objects for UI interactions
- [ ] Add comments for complex test logic

### Reminders for Code Suggestions

When suggesting code, always include:
1. The specific file location
2. Why this approach follows the project patterns
3. Reference to the Rules folder: `rules/TEST_CASE_RULES.md`
4. Mention required checks: type-check and lint

### Project Configuration

- **Language:** TypeScript (ES2022)
- **Framework:** Playwright
- **Module Type:** ESM (type: "module")
- **Config:** `playwright.config.ts` (testDir: `src/tests`)
- **TypeScript Config:** `tsconfig.json` with path aliases
